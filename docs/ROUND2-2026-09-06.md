# Round 2 — 2026-09-06: attendance truth, sign-in once, admin on real data

This is the ledger for the second round of the day, run straight after the
security hardening (`HARDENING-2026-09-06.md`). It answers a 15-point list;
each section names the point it closes, what changed, and why.

Everything here is in code and tested: **33 suites / 260 tests green**,
`bash build.sh` produces a working `dist/`, and the PWA was walked through in a
browser against `vercel dev` with the enforced CSP. Nothing has been deployed.

## 3 + 7 · The numbers now equal the college's, exactly

**What was wrong.** The app had three ways of drifting above the college:

1. `runAutopilotCheck` in `AppContext` auto-marked every past timetabled
   class as *present* the moment it was over ("predictions").
2. Students could mark classes the teacher had not uploaded yet, and those
   marks were added on top of the college totals until a "delta GC" guessed
   which ones the college had since absorbed.
3. Records the GC never got round to stayed in the sum.

So ADI showed more classes in Presence than in the college app.

**What changed.**

- `src/utils/attendance.js` — `getSubjectAttendance` returns the college's
  per-subject totals and nothing else. (`subject.initialAttended/Total` are
  those totals; the field names are historical.) `shouldCountLocalRecord`,
  `hasPredictions` and the coverage-date bridging are gone.
- `src/context/AppContext.js` — rewritten. Removed: `MARK_ATTENDANCE`,
  `REMOVE_ATTENDANCE`, `EDIT_ATTENDANCE`, all `*_AUTO_MARK` / autopilot
  actions and state, the delta GC in `ERP_OVERWRITE_ATTENDANCE`.
  `ERP_OVERWRITE_ATTENDANCE` now applies **downward** corrections too — the
  college is the truth even when it changes its mind. `ERP_OVERWRITE_CALENDAR`
  **replaces** history when the register covers every subject we already knew
  (a class the college removed disappears here too) and only merges when the
  register is partial, so a truncated page can never wipe months of history.
- **Migration for everyone, on next launch:** `LOAD_STATE` runs
  `keepOnlyErpRecords` — every record whose `source !== 'erp'` is dropped,
  holiday markers stay. Legacy state keys (`autopilotReview`,
  `autopilotDismissed`, `erpReauthSnoozeUntil`, `todayIncludedInSetup`,
  `weeklySummaryEnabled`) are deleted. The cloud copy is overwritten on the
  first save after that, so both devices converge.
- `useErpAutoSync` — the non-regression guard (`isNonRegressingErpUpdate`)
  is gone; only a malformed subject (no total, attended > total) is ignored.
  The register's own totals are applied whenever they differ.
- **Deleted** (all were ways to move the number or leftovers of them):
  `utils/backlog.js`, `PastAttendanceScreen`, `BacklogBanner`,
  `SyncFromPortalScreen` (manual totals entry), `utils/transparency.js`,
  `ProjectionTransparencyModal`, `utils/erpFreshness.js`, `AttendanceGraph`,
  `utils/summary.js` + `WeeklySummaryScreen`, the unreachable
  `screens/main/PlannerScreen/*` tree with its `SkipMode`/`FixMode`
  components, `BestBunkDayCard`, `PlannerModeToggle`, `DateHeader`,
  `EmptyDay`, and five unused Today cards.
- `EditSubjectsScreen` — rewritten: rename, colour, per-subject goal. No
  totals input, no "add subject" (a subject not sent by the college would
  never update). `SubjectDetailScreen` — history is read-only; the "Edit"
  modal and "marks by you" note are gone. `CalendarView` — no hollow
  "by you" dots; a part-attended day renders as its own state.
- Math re-check: the solvers in `attendance.js` were already exact
  (property tests in `attendanceMath.test.js`). What was wrong was the
  *inputs*, not the formulas. New guard: `src/utils/__tests__/attendanceTruth.test.js`.

**Trade-off accepted.** A student can no longer note "I attended today"
before the teacher uploads it. The college updates within a day or two; the
Today card says so ("No attendance recorded yet") instead of guessing.

## 2 · Sign in once. No more "session expired" prompts

**Root cause (three parts).**

1. This college's `appLoginAuthV2` **always** answers status 4 — an OTP is
   emailed on every login, trusted device or not (`erp-mobile-auth-decoded`
   memory, verified from the official app's HAR). So every automatic
   `reloginERP` the server ran *was* an OTP email.
2. The hardening added a 30-day session expiry. That forced a re-login —
   i.e. an OTP — every month, from our side.
3. When the student tapped "Skip for now", a 30-minute snooze let the
   3-minute periodic sync re-trigger the re-login. Prompt, skip, prompt.

**What changed.**

- `api/_data-session.js` — rewritten. It **never** calls `reloginERP`. A
  session that looks dead is confirmed by the college's own liveness probe
  **twice, 1.5 s apart**, and only then answered with
  `{ sessionExpired, needsOtp, reason }` — no ticket, no email. A session
  token this server cannot open (older format, rotated secret) is no longer a
  bare 401 that strands the app; it becomes the same card. Reasons are
  `dead`, `stale`, `invalid_token`, `expired`, `no_persistent`.
- `api/_session-utils.js` — `checkSessionAlive` only returns `false` for a
  **JSON** body with a session message; any HTML (maintenance page,
  Cloudflare, a login form served during an outage) is `null` = transient.
  Session and persistent tokens now expire after **365 days** (was 30/180).
  They still expire — a leaked pair dies within a year, and disconnecting
  revokes sooner — but the app no longer schedules OTPs for itself.
- `api/erp-session.js` — new action **`requestOtp`**: the one place after
  onboarding where a login (and therefore an email) can happen, and only
  because the student tapped. Rate limited 3 per 15 min per student, 10 per
  IP. A trusted device gets fresh tokens straight back; a changed password
  answers `needsLogin` so the app forgets the saved sign-in.
- Client: `ErpReauthModal` → **`ReconnectSheet`** (never auto-opens; step 1
  "Send code", step 2 enter it) + **`ReconnectCard`** on Today (banner slot,
  above announcements) + a "Sign in again" row in Settings. Auto-sync pauses
  while the card is up. Keep-alive pings (12 min, every user) and the snooze
  are gone. `useErpAutoSync` rewritten around this.
- Telemetry: every prompt is logged as `sessionEvent { type, reason }` and
  the admin **Sign-in prompts** panel shows who was asked and why.
- Guard: `api/__tests__/reconnect-flow.test.js` (zero login calls on a dead
  session; HTML is not dead; flip-flop probe is transient; requestOtp shapes;
  rate limit).

**What still needs one OTP:** the first sync after deploy for existing
users whose session token predates `iat` (they are answered
`reason: 'stale'`, shown the card once, and are done for a year), and any
genuine session death by the college (password change, ERP-side reset).

## 1 · Startup

**What was slow.** Four network round-trips ran *before* the first frame:
`/api/auth-token`, Firebase `signInWithCustomToken`, a Firestore read of the
semester doc, and `erpCheckSession` — then `AppNavigator` blocked again on a
Firestore read of `admin/config` for the maintenance/version gate.

**What changed.** `storage.js` splits `loadLocalState()` (AsyncStorage only)
from `loadCloudState()`. `AppProvider` paints from local immediately; the
cloud comparison, the migration and the session check run after paint and
update the screen if they have news (`dirtyRef` stops a late cloud copy from
overwriting something the student just changed). `AppNavigator` renders at
once and checks gates in the background, re-checking on foreground. Bailout
timer is 4 s (was 12 s) because only local storage can now delay it.

## 6 · Today on a day with no classes

`RestDayView` replaces the two-line "No classes today". It shows: where you
stand (overall %, hours, subjects below goal, skips to spare, how far the
college has updated), the next day with classes with a verdict per class,
this week as the register recorded it, the cheapest day to skip (only when
every subject on it can absorb it), and the three subjects that need you
most — each row opens the subject. All of it from the college's numbers.

## 8 · Insights on real data

`utils/insights.js` — `generateWeeklyReport` counts **only** register
records; a day the college has not uploaded is not a miss any more (it used
to be, so the weekly number sagged every morning). `getNextClassDay` is new.
`calculateBestBunkDay` prefers a *safe* day and reports whether the best day
is safe at all. `utils/streak.js` — a gap in the register no longer breaks a
streak; only a recorded absence does. Guard: `insightsErpOnly.test.js`.

## 9 · Admin

**Where "hundreds of users" came from.** Every login code that ever hit
`/api/auth-token { create: true }` got a `users/{code}` document, and the
roster listed all of them with "Student" and "SETUP PENDING" (the fields it
read were never written). Test runs, previews, mock logins and anyone who
opened the app and left at onboarding all counted.

**What changed.**

- `api/admin-analytics.js` — rewritten. A **student** is a user document
  with a real roll number (`/^\d{6,}$/`), i.e. someone who connected a
  college account; everything else is reported as `unfinishedSignups` and
  never mixed in. New metrics: `overview` (students, connected, active
  today/week/month, syncs and success rate 24 h, sign-in prompts and lost
  sign-ins 7 d, average attendance, students below goal, per-day sync
  sparkline), `sessionEvents`, and a roster shaped
  `{ users, unfinished: { count, olderThan7d } }` with real names,
  connection state, below-goal counts and "college updated through".
  Cache TTL is 2 min for live panels, 30 min for heavy aggregates;
  "Refresh all" bypasses it.
- `api/admin.js` — new actions **`purgeUnfinishedSignups`** (deletes idle
  codes with no college account, 300 per press, audited, with the user
  and push sub-collections) and **`listAuditLog`**.
- `storage.js` — the root user profile is only written once
  `erpRollNumber` exists, and now carries `studentName` and `setupComplete`,
  so the roster is right from the first sync.
- `AdminScreen` — rewritten on four tabs (Overview, Students, Health,
  Controls). Every panel has its own loading/error/retry; nothing renders a
  number it did not fetch. Parser-failure cards read the fields telemetry
  actually writes (`endpoint`/`message` — the old card read
  `component`/`error` and showed blanks). Loaded with `React.lazy`: its
  48 KB chunk is only downloaded for an admin.
- Controls verified end to end in code: maintenance mode and the version
  gate are read by `AppNavigator` (now also on foreground); flags gate
  `useErpAutoSync`; announcements render through `AnnouncementBanner`;
  revocation is enforced server-side and surfaced on the next sync.

## 10 · Android

- `utils/notifications.js` — rewritten. The "mark your attendance" evening
  nudge is gone (there is nothing to mark). Instead: a **morning plan** — one
  notification per class day for the next week, written from the timetable
  and the college's numbers ("Monday: 3 classes · Skip DMS, CN if you must.
  Attend DSA."), re-planned on every sync / foreground so it is never stale;
  and **goal alerts** after a sync when a subject drops below its goal or
  sits within 2 % of it. Android notification channel `daily-plan` is
  created (required on Android 8+). `App.js` wires both; both are
  Android-only and invisible on the PWA.
- Settings shows platform-specific controls only: Android gets "Morning
  plan" + "Goal alerts"; the PWA gets "Daily summary" (web push). The dead
  "Weekly summary" switch (no reader) is removed.
- `api/push-send.js` — the web push body is personal: each subscriber's
  semester doc is read once and summarised ("You're at 78.4% overall. 1
  subject below goal.").
- Haptics already no-op on web (`Vibration` is a no-op in react-native-web).

  soon" instead of 404-ing when it is not deployed.

  both. Mobile overflow: the app is RN; the landing page is a 520 px column.
